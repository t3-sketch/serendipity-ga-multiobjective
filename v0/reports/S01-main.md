## 実験条件

- MovieLens 100K。全体時刻でtrain 79,999件、validation 10,001件、test 10,000件に分割。同一timestampは区間をまたがせない。
- 学習済みユーザー751人・アイテム1,616件。条件を満たすvalidation 69人、test 51人（test正例780件）。test区間166人中97人は学習時点に存在しないユーザーで対象外。
- RecBole 1.2.1のSASRec、CPU 2スレッド、学習seed 42。9 epochでearly stopping、validation NDCGが最大のepoch 3を採用。validation NDCG@10は0.080356。
- 候補100件、出力10件。pymoo NSGA-II：40個体、50世代、search seeds 42/43/44。加重和は重み0〜1を0.1刻み。
- 最適化：平均関連度順位と平均`関連度順位 × ジャンル距離`。代表解の関連度下限はSASRec上位10件の平均の95%。

## Test結果

| 指標 | SASRec | 加重和・代表解 | NSGA-II・代表解 |
|---|---:|---:|---:|
| Recall@10 | 0.090679 | 0.001013 | 0.001013 |
| NDCG@10 | 0.105176 | 0.022050 | 0.022050 |
| 候補Recall@100 | 0.355381 | 0.355381 | 0.355381 |
| 平均関連度順位 | 0.996809 | 0.970433 | 0.970433 |
| 平均ジャンル距離 | 0.740405 | 0.954192 | 0.954192 |
| 平均`s_proxy` | 0.738042 | 0.925682 | 0.925682 |
| held-out高評価×距離 / 10 | 0.046970 | 0.014944 | 0.014944 |
| 選択時間 / user | 約0.0008 ms | 約0.151 ms | 約133.6 ms |

加重和は`w*r + (1-w)*s_proxy`の重み掃引から、NSGA-IIと同じ関連度条件で選んだ代表解。推論時間は共通部分として除外。NSGA-IIの時間は1 search seed当たり。3 seedの推薦は51人×10件×3回＝1,530順位すべてで加重和と一致した。
この表の加重和は保存CSVの`weighted_proxy_selected`であり、別の`weighted_distance_selected`ではない。

ユーザー単位の対応付きbootstrap（2,000回）によるNSGA-II − SASRecの差：

| 指標 | 平均差 | 95%区間 |
|---|---:|---:|
| NDCG@10 | −0.083126 | [−0.144864, −0.033604] |
| Recall@10 | −0.089666 | [−0.155135, −0.031228] |
| held-out高評価×距離 / 10 | −0.032026 | [−0.056517, −0.012176] |
| 平均`s_proxy` | +0.187640 | [+0.169494, +0.207248] |

3 search seedsはユーザー内で平均してからbootstrapしている。学習seedは1つ。NSGA-II対加重和の差は数値丸めの範囲でゼロであり、CSV中の約1e-18の差に意味はない。

## 判断

**課題:** 関連度を維持しつつ、普段の嗜好外にある価値のある候補を選びたい。

**仮説:** 関連度と嗜好外距離の積を最大化すれば、興味を持てそうな嗜好外候補が増える。

**根拠:** Taste-Broadeningの「普段との違いと興味の両立」を計算可能な代理値に置き換えた。関連度・距離を別々に足す比較と、同じ積を使う加重和比較を置いた。

**結果:** 代理値の最大化には成功したが、held-out高評価に対する性能は悪化した。この設定を価値ある発見の推薦器として採用する根拠は得られていない。

今回、`s_proxy`だけを最大化した上位10件が全51人で関連度下限を通過した。候補100件はもともと全カタログで高順位にあるため、順位値95%の下限は強い制約になっていない。しかも順位値の低下幅とNDCGの低下幅は対応しない。**「95%制約があるから精度は維持される」という解釈は成立しない。**

NSGA-IIは途中のトレードオフ解を増やしたが、採用する代表解には寄与せず、加重和の約885倍の選択時間を要した。このアイテム加算型の目的と運用点では、NSGA-IIを採用する優位性は確認できない。これは他の目的関数やリスト間相互作用を含む問題でのNSGA-IIを否定する結果ではない。

次の設計判断は、関連度順位を価値の代理として使う妥当性と、関連度下限の設け方を見直すこと。変更する場合はvalidationで選び、新しい検証として記録する。今回のtest結果を見てパラメータだけを合わせ直すことは行っていない。音楽の試聴・Fortuitousness・実際の興味や後続探索は未計測。
